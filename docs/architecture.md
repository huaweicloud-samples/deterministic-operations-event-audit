# 架构设计

## 1. 总体架构

本服务是一个事件驱动的审计系统：业务系统将实体变更事件投递到事件网格，由订阅规则路由到函数完成审计处理。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              业务系统 / 事件源                                │
│                    （发布 CloudEvents 格式的审计事件）                        │
└───────────────────────────────────┬─────────────────────────────────────────┘
                                    │ PUT CloudEvents
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                          华为云事件网格（EG）                                 │
│  ┌──────────────────────────┐        ┌──────────────────────────────────┐   │
│  │  自定义事件通道           │        │  事件订阅 audit-to-function      │   │
│  │  audit-events-channel    │───────▶│  · 源：audit-event-source        │   │
│  │                          │        │  · 过滤：source StringIn         │   │
│  │  自定义事件源             │        │  · 目标：HC.FunctionGraph（异步）│   │
│  │  audit-event-source      │        └───────────────┬──────────────────┘   │
│  └──────────────────────────┘                        │                      │
└──────────────────────────────────────────────────────┼──────────────────────┘
                                                        │ 委托授权调用
                                                        ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                          FunctionGraph 函数                                   │
│                  audit_event_handler（Node.js 18.15 / 256MB）                 │
│                                                                              │
│   ① 解析事件（兼容 CloudEvents 与直接调用两种入参）                            │
│   ② 生成审计记录（record_id / 实体 / 操作 / 操作者 / 时间）                    │
│   ③ 归档到 OBS                                                                │
│   ④ 删除类操作触发 SMN 通知                                                   │
│   ⑤ 全量日志输出到 LTS                                                        │
└───────┬──────────────────────────┬──────────────────────┬────────────────────┘
        │                          │                      │
        ▼                          ▼                      ▼
┌──────────────────┐    ┌──────────────────────┐   ┌──────────────────┐
│      OBS         │    │ GaussDB(for Mongo)   │   │      SMN         │
│  审计归档         │    │ 事件明细存储（可选）  │   │   删除通知        │
│  ──────────      │    │ ──────────────────   │   │ ──────────       │
│  生命周期：30天   │    │ 默认关闭（按月订阅）  │   │ 主题 + 订阅       │
└──────────────────┘    └──────────────────────┘   └──────────────────┘
        ▲
        │  日志、指标
┌──────────────────┐
│      LTS         │
│  日志组 / 日志流  │
└──────────────────┘
```

## 2. 组件职责

### 2.1 事件网格（EG）

| 资源 | 作用 |
|------|------|
| 自定义事件通道 `audit-events-channel` | 事件的接收总线，业务系统向其投递事件 |
| 自定义事件源 `audit-event-source` | 标识事件来源，作为订阅过滤依据 |
| 事件订阅 `audit-to-function` | 定义「源 → 目标」的路由规则，配置过滤条件与投递方式 |

订阅的过滤规则：

```json
{
  "source": [
    {
      "op": "StringIn",
      "values": ["audit-event-source"]
    }
  ]
}
```

订阅的目标配置：

| 字段 | 值 | 说明 |
|------|-----|------|
| `provider_type` | `OFFICIAL` | 使用官方目标类型 |
| `name` | `HC.FunctionGraph` | 目标为函数工作流 |
| `detail.urn` | 函数 URN | 指向审计处理函数 |
| `detail.invoke_type` | `ASYNC` | 异步调用，不阻塞事件投递 |
| `detail.agency_name` | 委托名称 | EG 通过该委托获得调用函数的权限 |
| `transform.type` | `ORIGINAL` | 不做转换，原样投递事件 |

### 2.2 FunctionGraph 函数

| 配置项 | 值 |
|--------|-----|
| 函数名 | `audit_event_handler` |
| 运行时 | Node.js 18.15 |
| 入口 | `index.handler` |
| 内存 | 256 MB |
| 超时 | 60 秒 |
| 代码方式 | inline（内联，无外部依赖） |

处理逻辑：

1. **事件解析**：优先识别 CloudEvents 的 `data` 字段，其次识别 `detail` 字段，最后回退为事件本身
2. **记录构建**：生成唯一 `record_id`，规范化实体类型、实体 ID、操作类型、操作者、时间戳
3. **归档**：按 `{entityType}/{entityId}/{timestamp}.json` 的键规则归档到 OBS
4. **通知**：当 `operation === 'delete'` 时触发 SMN 通知
5. **返回**：统一返回 `statusCode` 与 `body`，便于调用方判断结果

### 2.3 存储与通知

| 服务 | 用途 | 配置 |
|------|------|------|
| OBS | 审计事件归档 | 标准存储，生命周期规则 30 天后过期，私有读写 |
| GaussDB(for Mongo) | 事件明细存储 | 默认关闭；开启需按月订阅 |
| SMN | 删除类事件通知 | 主题 `deleted-entities-notification` |
| LTS | 运行日志 | 日志组 `audit-events-log-group`，日志流 `audit-events`，保留 7 天 |

### 2.4 身份与权限

事件网格调用 FunctionGraph 需要显式授权：

| 配置 | 值 |
|------|-----|
| 委托名称 | `EG_TARGET_AGENCY` |
| 委托类型 | 云服务委托 |
| 被委托服务 | 事件网格 |
| 授予权限 | `FunctionGraph FullAccess` |

## 3. 网络设计

| 资源 | 配置 |
|------|------|
| VPC | `10.0.0.0/16` |
| 子网 | `10.0.1.0/24`，网关 `10.0.1.1` |
| 安全组 | 入方向放通 TCP 8635（文档数据库）、TCP 443（HTTPS）、ICMP，源为 VPC 内网段 |

## 4. 数据流时序

```
业务系统          事件网格          委托授权        FunctionGraph        OBS/SMN/LTS
   │                 │                 │                 │                  │
   │  PUT 事件        │                 │                 │                  │
   ├────────────────▶│                 │                 │                  │
   │  failed_count=0  │                 │                 │                  │
   │◀────────────────┤                 │                 │                  │
   │                 │ 匹配订阅过滤规则  │                 │                  │
   │                 ├────────────────▶│                 │                  │
   │                 │                 │  以委托身份调用   │                  │
   │                 │                 ├────────────────▶│                  │
   │                 │                 │                 │  解析 / 留痕      │
   │                 │                 │                 │  归档 ───────────▶│
   │                 │                 │                 │  删除则通知 ──────▶│
   │                 │                 │                 │  写日志 ─────────▶│
   │                 │                 │                 │◀─────────────────┤
   │                 │  返回调用结果     │                 │                  │
   │                 │◀────────────────┴─────────────────┤                  │
```

## 5. 扩展性设计

| 维度 | 说明 |
|------|------|
| 新增事件源 | 增加事件源并补充订阅的 `sources` 块即可，无需改动函数 |
| 新增目标类型 | 事件网格支持 SMN、Kafka、EG、FunctionGraph 等多种目标，可在同一订阅下并列配置 |
| 函数横向扩展 | FunctionGraph 按请求量自动弹性伸缩，无需预置容量 |
| 数据分级 | 冷数据留 OBS，热查询数据可选开启文档数据库 |

## 6. 部署拓扑

所有资源部署在单一区域内（默认 `cn-north-4`），由 Terraform 统一编排，资源命名统一带 `environment` 后缀以便多环境并存。
